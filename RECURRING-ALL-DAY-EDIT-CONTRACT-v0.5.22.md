# Materialized recurrence date-range contract — v0.5.22

LifeGrid recurrence is a group of materialized sibling Event records linked by `recurringGroupId`; it is not a generated master/rule engine. Every repeated Event uses the same pure date-span helper. The occurrence start date is shifted by the recurrence frequency and its end date is shifted by the same calendar-day span. Same-day all-day, timed, and approximate occurrences use `endDate = date`; overnight and multiday occurrences preserve the first occurrence's inclusive calendar span. Each materialized occurrence must pass `temporalErrors` without timezone conversion.

When an existing all-day Event's end date is explicitly edited, that value is authoritative and ordinary temporal validation rejects a value before its start. When the end was not edited and the start changes, a valid original inclusive duration is preserved; a missing/stale original end becomes the new start date. When neither date field was edited, a valid stored range is retained and a missing/stale end is repaired to `endDate = date`. This repairs legacy invalid materialized records even during a notes-only edit.

For a notes-only edit in a materialized group, the editor shows **Entire series** (default) and **This event**. Entire series updates `notes`, `aiNotes`, and `sourceNotes` on every sibling and normalizes stale all-day sibling ranges; This event updates and repairs only the selected record. Structural edits remain single-event edits. LifeGrid does not expose or claim an unsupported “This and following” scope.
